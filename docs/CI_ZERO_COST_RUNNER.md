## Option A — Run verification locally now

On your **personal development Windows workstation**, clone/check out the feature branch and run from the repository root:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Invoke-PRChecks.ps1
~~~

The script runs the same categories as the existing CI workflow: parse all PowerShell, PowerShell 5.1 offline suite, Node browser tests (including Intelligence Workbench and sync tests), Python Nexus static integration test, and the local stack compatibility probe. It fails if a required tool is missing; it never installs software, calls Git.mil, unlocks ARC, or invokes the GenAI endpoint.

For a **limited** PowerShell-only verification:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Invoke-PRChecks.ps1 -CoreOnly
~~~

This intentionally exits **2** and labels the report **PARTIAL** even if the covered tests pass. A partial run must not be represented as equivalent to a green required CI check. Full success returns **0**; actual test failures return **1**.

The local script does not post a GitHub commit status. It is useful evidence for manual review, but it **does not satisfy** a required GitHub branch-protection check.

## Option B — Recommended: register a self-hosted Windows GitHub runner

**Do this on an authorized personal or designated development machine, not a managed Navy/Nautilus workstation.** The repository is hosted on public GitHub.com, and neither runner configuration nor its working directory may contain Git.mil/internal Navy source material or credentials.

1. Open the repository: https://github.com/sun-of-anton/cascade/settings/actions/runners
2. Select **New self-hosted runner**, **Windows**, **x64**.
3. Follow GitHub's **current** on-screen download, checksum/verification and configuration commands on your designated machine. The registration token is generated by GitHub and expires; **do not commit it** or paste it into issues/logs.
4. Choose a dedicated runner identity and a clean, access-restricted working directory. Prefer least-privilege, isolated execution of **trusted repository-owned PRs only**; never run arbitrary unreviewed fork content.
5. Install/provide test prerequisites on that machine if authorized: **Windows PowerShell 5.1**, Node.js for JavaScript tests, Python for the static Nexus check. The workflow itself will not install Python or Node; if either is missing, the test fails explicitly.
6. Launch the runner using GitHub's instructions (interactive or appropriately configured service); verify the dashboard reports **Idle**.
7. The new runner must have matching labels **self-hosted**, **Windows**, **X64**. Cascade's existing PR checks can then run without GitHub-hosted runner minutes.
8. Re-run the latest PR check if it does not automatically start. Require actual successful test results and investigate failures before manual merge.

GitHub's official instructions: https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners

## Security boundaries

- A GitHub.com self-hosted runner must execute only **Cascade's public-GitHub repository test fixtures and approved code**, not Git.mil source or restricted Navy workflows. Production autonomous PO compute is a separate, internally approved architecture.
- Disable runner access to untrusted forks, use protected branch workflows and restrict repository contributors appropriately. A PR can contain modified workflow/script steps, so even a private repository requires careful trust management.
- Keep runner OS, Git and runner application patched; apply least privilege; avoid elevated runner accounts and persistent credentials.
- Because self-hosted runner workspaces persist, regularly clean working directories, rotate credentials and restrict network access. Use a dedicated machine/VM where possible.
- No Git.mil PATs, ARC vault exports, CAC material or enterprise secrets in this runner.
